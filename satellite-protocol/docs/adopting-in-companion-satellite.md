# Plan: adopt `@companion-app/satellite-protocol` in companion-satellite

Repository: [bitfocus/companion-satellite](https://github.com/bitfocus/companion-satellite). File and
line references are against `main` at `5fb1fbb` (release 3.5.0); re-check them before starting.

## Context

companion-satellite carries its own copies of the Satellite protocol, all derived from Companion:

- `satellite/src/client/parser.ts` is a copy of Companion's `parseLineParameters`, including its own
  `BANNED_PROPS` literal.
- `CompanionSatelliteClient#sendMessage` (`satellite/src/client/client.ts:853`) is a copy of Companion's
  serialiser. It quotes string values **without escaping** `"` or `\`, so such a value is corrupted on
  the wire. Companion fixed this in the shared package.
- Feature gating in `handleBegin` (`client.ts:440-485`) uses `semver.lt`/`semver.lte` directly. `semver`
  **throws** on an invalid version, so a malformed `ApiVersion` in `BEGIN` throws out of the line
  handler instead of being treated as an unsupported server.
- The surface layout and config field types are generated by `tools/schema_compile.mts`, which reads
  `../../companion/assets/*.schema.json`. That means a **sibling Companion checkout** is needed to
  regenerate them.
- The receive loop (`client.ts:363-377`) has no bound on the length of an incomplete line.

The package replaces all of these with Companion's own definitions. It has no dependencies besides
`zod` (only pulled in by the `/schemas` entry point) and uses no node built-ins.

## Steps

1. **Add the dependency** to `satellite/package.json`: `"@companion-app/satellite-protocol": "^0.1.0"`.
   satellite's tsconfig extends `@tsconfig/node24` (`module: nodenext`), so the package's subpath
   exports (`/codec`, `/versions`, `/constants`, `/schemas`) resolve as-is.

2. **Parser.** Delete `satellite/src/client/parser.ts` and `satellite/src/client/__tests__/parser.test.ts`.
   The package's tests and conformance corpus cover the same cases. In `client.ts`:
   - import `parseLineParameters` and the `ParsedParams` type from `@companion-app/satellite-protocol/codec`
   - replace the 9 `Record<string, string | boolean>` param types with `ParsedParams`
     (`string | true | undefined`). The existing `=== '1' || === true` and `typeof … === 'string'` checks keep
     working unchanged.

3. **Framing.** Replace the body of `_handleReceivedData` (`client.ts:363`) and the command split in
   `handleCommand` (`client.ts:379-382`):

   ```ts
   private readonly lineBuffer = new SatelliteLineBuffer(MAX_LINE_LENGTH)

   private _handleReceivedData(data: string): void {
   	this._lastReceivedAt = Date.now()
   	const { lines, overflow } = this.lineBuffer.push(data)
   	for (const line of lines) this.handleCommand(line)
   	if (overflow) {
   		this.emit('log', 'Received line too long, reconnecting')
   		this.socket?.destroy()
   	}
   }

   private handleCommand(line: string): void {
   	const { command: cmd, body } = splitSatelliteCommand(line)
   	const params = parseLineParameters(body)
   	// ...unchanged
   ```

   Replace the two `this.receiveBuffer = ''` resets (`client.ts:241`, `:271`) with
   `this.lineBuffer.clear()`, and remove the `receiveBuffer` field.

4. **Serialiser.** Replace the body of `sendMessage` (`client.ts:853-877`) with
   `this.socket?.write(formatSatelliteMessage(messageName, status, deviceId, args))`, and delete the local
   `SatelliteMessageArgs` type in favour of the package's. Values containing `"` or `\` are now escaped,
   which Companion has always understood.
   - `formatSatelliteMessage` **throws** if a string value contains a newline, as that would split the
     message. Check the callers: `sendMessage` is reached from device events, so a throw must not escape
     into an event emitter unhandled. Wrap the call, or confirm no value can contain a newline. Values are
     ids, numbers, base64 and hex today.
   - Leave the raw `PONG ${body}\n` write (`client.ts:387`) as it is; it echoes the body verbatim.

5. **Version and CAPS gating.** Replace the `semver` checks:

   ```ts
   const apiVersion = this._companionApiVersion ?? ''
   this._companionUnsupported = !isApiVersionAtLeast(apiVersion, MINIMUM_PROTOCOL_VERSION)
   // ...
   const features = getSatelliteFeatures(apiVersion, null)
   this._supportsLocalLockState = features.lockState
   this._supportsSurfaceManifest = features.surfaceManifest
   this._supportsDeviceSerial = features.deviceSerial
   this._supportsLedsCapability = features.leds
   const expectCaps = features.caps
   ```

   In `handleCaps` (`client.ts:632`), use `getSatelliteFeatures(apiVersion, params)` for `subscriptions`
   and `nonSquareBitmaps`. Keep the `BITMAP_FORMATS` list parsing, which negotiates a format rather than
   gating a feature. `isApiVersionAtLeast` returns false for a malformed version instead of throwing, which
   fixes the crash above. Then drop the `semver` import from `client.ts`. `semver` is still used by
   `tools/update_builtin_surface_modules.mts`, so keep it in the root `package.json`, but `satellite/package.json`
   can drop `semver` and `@types/semver`.

6. **Schema types.**
   - Delete `tools/schema_compile.mts`, the root `build:schema` script (`package.json:31`), the
     `json-schema-to-typescript` devDependency (`package.json:58`), and
     `satellite/src/generated/SurfaceManifestSchema.ts` + `SatelliteConfigFieldsSchema.ts`. Keep
     `generated/openapi.ts`; it comes from `build:openapi`.
   - Change the imports in `satellite/src/translateSchema.ts`, `satellite/src/client/client.ts` and
     `satellite/src/__tests__/translateSchema.test.ts` from `./generated/…Schema.js` to `import type { … } from '@companion-app/satellite-protocol/schemas'`. Type-only imports don't bundle zod.
   - All 14 type names used today exist in the package with the same names: `SatelliteSurfaceLayout`,
     `SatelliteControlDefinition`, `SatelliteControlStylePreset`, `SatelliteConfigSize`, `SatelliteLedsConfig`,
     `ConfigField`, `CommonFields`, `CheckboxField`, `DropdownChoice`, `DropdownField`, `NumberField`,
     `StaticTextField`, `TextInputField`, `SatelliteConfigFields`. They are `z.infer` types rather than
     json-schema-to-typescript output, so expect small differences, such as no index signatures, and
     optional fields typed `T | undefined`. Fix whatever `tsc` reports.
   - Optional: validate a manifest with `SatelliteSurfaceLayoutSchema.safeParse` before sending
     `LAYOUT_MANIFEST`, to catch a bad surface plugin locally. This does bundle zod.

7. **Rotation.** Already compatible. `rotate` (`client.ts:705`) sends a signed `DIRECTION`. Companion
   now truncates it to a whole number of steps and clamps it to ±100. If you want to only send a step
   count when Companion advertises it, gate on `features.rotaryAmount`; older Companion only reads the sign.

## Behaviour changes to check

- Escaped `"`/`\` in sent values. Companion has always parsed these.
- A malformed `ApiVersion` now marks the server unsupported instead of throwing.
- A peer sending more than 2MB without a newline now closes the connection.
