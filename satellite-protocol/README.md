# @companion-app/satellite-protocol

Definitions of the [Bitfocus Companion](https://github.com/bitfocus/companion) Satellite API wire
protocol, shared by Companion and its clients such as
[companion-satellite](https://github.com/bitfocus/companion-satellite).

It depends only on `zod`, and uses no node built-ins, so it can be used from node, browsers and bundlers.

## Contents

- **Codec**: `parseLineParameters`, `formatSatelliteMessage`, `isTruthy`/`isFalsey`, `parseSatelliteBitmapFormat`
- **Constants**: `API_VERSION`, line and grid limits, `SATELLITE_BITMAP_FORMATS`
- **Versions**: `SATELLITE_FEATURES`, `getSatelliteFeatures(apiVersion, caps)`, `compareApiVersions`.
  An API version says whether a feature _exists_; a CAPS flag says whether it is _enabled_ on this
  connection.
- **Schemas**: `SatelliteSurfaceLayoutSchema` and `SatelliteConfigFieldsSchema` (zod), with inferred types

## Assets (for clients in other languages)

- `assets/satellite-surface.schema.json`, `assets/satellite-config-fields.schema.json`: JSON schemas
  for `LAYOUT_MANIFEST` and `CONFIG_FIELDS`
- `assets/satellite-api-features.json`: the feature table
- `assets/satellite-protocol-corpus.json`: conformance cases for parsing and formatting lines. Any
  implementation of the protocol can load this and check it agrees.

The schema and feature JSON files are generated by `yarn build:satellite-schema` at the root of the
Companion repo.

## Versioning

The package version is independent of the API version it implements. `API_VERSION` is exported.

## Releasing

1. Bump `version` in `satellite-protocol/package.json` and commit
2. Push a tag `satellite-protocol-v<version>` (e.g. `satellite-protocol-v0.1.0`)

The `satellite-protocol-release` workflow publishes it to npm. Versions containing a `-` are
published with the `next` dist-tag.
